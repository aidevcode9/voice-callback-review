# Text review design exploration

Mode: Operate. Scope: two static prototype directions for the same local review task. Audience/job: owner demonstrating and testing fictional transcripts for senior engineers. Primary action: explicitly classify a saved version with a selected model; inspect evidence and append human judgment. Proof: fictional transcript snapshots and clearly simulated outcomes. No inference or production implementation.

## Grounded visual exploration

Seven source systems, ordered by task resonance: (1) scientific peer-review annotations, cool white/forest ink with highlighted passages; (2) library finding aids, warm gray/blue ink and a compact index; (3) conference program typography, navy/white with aligned schedules; (4) museum catalog indexing, white/charcoal and structured metadata; (5) cartographic legends, pale gray/deep green with explicit semantic keys; (6) technical standards publications, cool paper/indigo with a wide reading field; (7) civic wayfinding, white/teal and high-clarity labels. Layout and controls remain native web workspace patterns; these sources supply type, palette, density and a signature evidence treatment only.

The seed assigned 6: Casebook uses the standards-publication type/density discipline and a full-width evidence reading field. The top candidate becomes Review desk, an annotation-led side-by-side work area. Both are built because the owner explicitly requested two rendered alternatives before choosing. Seed: seed:15bb05bc61674be4. The remote retry returned catalog challengers; none supersedes the owner's requested text-first Operate workspace. Record-sleeve encoding loses clarity; ticket-wallet ritual adds unnecessary steps; acetate tabs offer a useful active-version distinction; bitmap specimen loses reading comfort; event-catalog density helps compact navigation but loses transcript clarity; variable-font display loses both audience fit and product clarity. Declined challengers contributed discipline: explicit active selection, compact navigation and a consistent type hierarchy, not borrowed ornament.

## Direction contract

THESIS: A Review desk keeps source and judgment adjacent for repeat testing; B Casebook leads with a decision band and a broad transcript for guided reading. Both make an earlier run's exact text inspectable.

OWN-WORLD: A uses a sage rail, forest action color, white work area, restrained sans hierarchy and amber evidence marks. B uses an indigo header, cool blue-gray ground, wider white reading field and the same semantic outcome colors. Familiar selects, buttons, disclosures and text editing in each.

STORY: Load or paste text, save version, choose model, explicitly submit, inspect rule/reason/highlight, append human decision, revisit history. Never confuse simulation with measured output.

FIRST VIEWPORT: A has a 235px case rail, 26px case title, flexible transcript and 330px decision column; primary submission sits under transcript. B has horizontal case navigation, a two-column recommendation/review band and full-width transcript, followed by explicit classification and history. At 390px both become sequential, retaining readable text and every action.

FORM: Grounded candidate 6 and candidate 1, seed:15bb05bc61674be4. Code-first app prototypes. Signature interaction: selecting a prior run restores its original transcript/evidence without changing the newest saved version.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Open decisions and constraints

At this historical design checkpoint, A was the agent recommendation and no production visual world was selected. The owner later selected A; SRC-024 later deferred audio to the roadmap. Screenshot provenance is the local browser capture script; no generated artwork is used.

Production follows A: case rail, adjacent transcript/recommendation/human-review areas, history and on-demand provenance. B is retained as an alternative artifact, not a second production theme.
