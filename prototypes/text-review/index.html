Two ways to review a call

Voice Callback Review · interactive design prototypes. All cases, recommendations, processing states, and timings here are simulated. No model or API is connected.

Both directions support the same workflow. Load a fictional case or paste text, choose a model, explicitly classify, inspect exact evidence, and save a separate human decision. Audio comes later.

A · Review desk

A persistent case rail, transcript, and decision column keep evidence and judgment together. Recommended for repeated testing and comparing runs. The tradeoff is a denser desktop workspace.

Try the review desk

B · Casebook

A horizontal case navigator and a full-width decision band lead into a roomy transcript. Better for a guided walkthrough and long reading; moving through many cases takes more vertical space.

Try the casebook

What to try

Edit the transcript and save a new version. Inspect the selected classifier without submitting. This prototype shows the one configured Qwen classifier. Classify explicitly, then inspect an earlier run. Use the prototype controls to simulate a timeout, malformed output, unavailable runtime, or loading. Save a human decision and verify that the model result stays intact.

Prototype history is stored in this browser under separate keys for each direction. Reloading preserves it; “Reset prototype” clears only this direction’s sample workspace. No frozen project data is loaded or changed.

Open either interactive prototype at a narrow width to compare the mobile layout. The verification script regenerates local screenshots; generated captures are not checked into Git.
